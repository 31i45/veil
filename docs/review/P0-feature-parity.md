# P0 功能对标评审：Veil vs Typora

> 评审日期：2026-10-26
> 评审对象：Veil 工作树（阶段 C 完成，573 测试全绿）
> 标杆：Typora 1.14（官方站抓取于 2026-10-26；页面标注 NEWS Jul 19 Typora 1.14）
> 配套产物：[P1 CommonMark 一致性报告](P1-commonmark-conformance.md)
> 性质：**功能存在性对标**，不评价实现质量，不做同机性能与用户盲测（那是 P2/P4）

## 1. 口径与边界

1. 「已有」= 代码中存在完整用户路径，且有测试或明确交互入口。
2. 「部分」= 有路径但有明确边界（只支持子集、只读、仅有渲染无编辑、仅单平台）。
3. 「缺失」= 代码中不存在该能力。
4. Typora 为闭源产品，功能栏依据官方产品页与公开 Markdown 参考；标 `†` 为官方页明确列出，标 `?` 为未在官方页核实、需实机复核。
5. Veil 栏一律以**代码与测试**为准，不采信 README（README 已出现数字漂移：444 测试/121 依赖 vs 实际 573/191）。

## 2. 结论摘要

**Veil 目前不能整体对标 Typora，更不能宣称超越。**

| 判定 | 结论 |
|---|---|
| 核心写作闭环（打开→写→保存→查找替换→大纲） | 基本可用，部分场景可对标 |
| 功能覆盖 | 98 项抽查：**已有 35 / 部分 18 / 缺失 45**（36% / 18% / 46%） |
| 规范兼容性 | CommonMark 0.31.2：块结构 **66.1%**、导出 HTML **75.0%**、行内 **69.2%**（P1） |
| 资源/延迟 | 自测数据领先（10 万字 p95 4.07ms、17.3MB、5.23MiB），但未与 Typora 同机实测 |
| 工程质量 | 五类状态模型、零手工失效、573 测试，属于**自证优势**，不能替代产品力 |
| 跨平台 | 仅 Windows 实现（Mica/标题栏为 Windows 专属），macOS/Linux 未验证 |

一句话：**Veil 的「编辑内核」有资格挑战，「产品」还是挑战者。**

## 4. Veil 的真实优势（不夸大）

1. **源码即真值 + 光标展开**：不存在 Markdown 与富文本两份状态，往返字节一致；这是与 Typora「隐藏标记」不同的编辑哲学，对纯文本洁癖用户更有吸引力。
2. **资源与延迟自测数据好**：10 万字 p95 4.07ms、内存 17.3MB、二进制 5.23MiB（README 记录，需 P2 同机复测）。
3. **CJK/IME 是一等公民**：组合期、候选框、CJK 粗斜体有专门测试。
4. **工程可维护性**：五类状态模型、因果键缓存、零手工失效、573 测试、clippy 零警告；这是长期资产，但用户不会为此付费。
5. **单文件、离线、零运行时**：部署与隐私优势。

## 5. 对标 Typora 的十个硬缺口（P0 级）

1. 表格单元格编辑与行列操作（Typora 的日常高频功能）
2. 宽松列表 / 多段列表项（真实文档极常见）
3. Setext 标题、缩进代码块、HTML 块（CommonMark 基础能力）
4. 引用式链接 / 引用定义 / 自动链接 / 内链
5. 图片拖拽、缩放、非 PNG 格式
6. PDF 导出（Typora 的核心卖点之一）
7. 文件树、最近文件、会话恢复
8. 专注模式 / 打字机模式 / 源码模式 / 全屏 / 行号
9. 字数统计、拼写检查、设置界面
10. 跨平台（macOS/Linux）与真实窗口稳定性证明

## 6. 判定

- **「对标」不成立**：功能覆盖 36% 已有、46% 缺失；兼容性 66–75%；导出仅 HTML。
- **「局部领先」成立但需实证**：性能/资源/CJK/工程结构，必须做 P2 同机实测后才能对外说「领先」。
- **「超越」不成立**：没有一项经过外部裁判（规范、同机基准、盲测）证明全面优于 Typora。

## 7. 建议

两条路线必须选一条，不要混着走：

- **A. 产品对标路线**：先按 P1 修兼容性（Setext/缩进代码/引用定义/宽松列表），再补十个硬缺口中的前六项；目标是一年内做到「核心写作不输」。
- **B. 差异化路线**：不与 Typora 比功能数量，把「源码真值 + 极低延迟 + 单文件 + CJK/IME + 可复现架构」做到极致；目标用户是 Markdown 洁癖与长文作者。

无论选哪条，P1 的兼容性修复都是前置条件——否则「源码真值」会在真实文档里频繁露馅。
