# ADR-006: 外部文件变更 —— 只提示，不自动重载

## 状态：已采纳（2026-10-25）

## 背景

INSTANCE §5 输入点 ⑤：当前文档可能被外部编辑器改写或删除。此时自动重载会静默丢弃用户未保存的编辑；静默自动保存则会覆盖外部版本。切片 16 需要决定：监听机制、线程模型，以及「检测到之后做什么」。

## 决策

1. **监听接缝**：`FileWatcher` trait 定义在 `veil-egui`（`watch`/`unwatch`/非阻塞 `poll`，事件只有 `Changed`/`Removed`），产品层注入 notify 8 实现。实现监听**父目录（非递归）**并按文件名过滤：tmp+rename 式原子保存与外部编辑器替换都能感知，直接监听文件会在 rename 后失效。
2. **线程模型**：notify 事件线程只把事件写入 `std::sync::mpsc` 通道；主线程在 winit `about_to_wait` 中轮询。有路径时以 300ms `WaitUntil` 唤醒（约 3.3 次/秒），草稿无路径则完全休眠。不引入 `EventLoopProxy` 与自定义用户事件，事件循环保持泛型无关。
3. **检测只改状态，不碰内容与磁盘**：读盘后与基线/已备份版本比较。磁盘内容 == 基线（含自身保存触发的事件）忽略；同一外部版本只提示一次；「已备份」与「待备份」分开呈现（`ExternalState::Changed/BackedUp/Missing`，标题与状态栏共用）。
4. **备份仍在覆盖前一刻执行**：检测阶段不落副本，避免外部程序每次保存都在文档旁积一份备份；脏文档一旦检测到外部修改即挂起自动保存，手动/自动保存沿用既有「先备份再覆盖」路径。
5. **删除**：提示「文件缺失」，不挂起自动保存——磁盘已无外部内容可保护，继续编辑时自动保存重建文件比丢失用户文本更安全。

## 后果

- 好：用户编辑永不因外部变更被静默丢弃或覆盖；检测、提示、备份的证据链完整（同一版本不重复提示、恢复可读有提示）；监听失败降级为状态栏提示，不阻塞编辑；策略层 headless 可测（`FakeWatch` 注入脚本事件）。
- 坏：直接依赖达到预算上限 8/8（新增 notify）；空闲时约 3.3 次/秒唤醒；不提供「一键重载外部版本」入口（v1 需手动重新打开）。
- 约束：后续任何新功能不得再增加直接依赖，需先替换现有依赖或提升预算并记录理由。

## 替代方案

- **自动重载外部内容**：实现简单，但会静默丢弃未保存编辑；否决。
- **检测后立即写冲突副本**：会在外部程序高频保存时产生副本堆积；否决（备份延迟到覆盖前）。
- **监听线程直接回调 UI / EventLoopProxy 唤醒**：需要把事件循环改为自定义用户事件泛型，耦合更重，收益仅是去掉 300ms 轮询；否决。
- **手写 ReadDirectoryChangesW / inotify**：零依赖但需自管重叠 I/O、缓冲区与失效重建，风险与代码量高于 notify；否决。
- **直接监听文件路径**：rename 后监听点失效，无法覆盖原子保存；否决。
