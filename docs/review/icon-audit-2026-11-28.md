# 应用图标多尺寸审计（2026-11-28）

> 范围：`icons/veil.ico`（exe / 安装包 / 任务栏）、`icons/veil-32.rgba`（窗口图标）、`icons/Markdown.png`（文档图标设计稿）。
> 方向：纯白圆角底 + 黑色 V；本次只做多尺寸度量与必要光学微调，未更换字形、未加装饰。

## 方法

- Pillow 解析 ICO 目录，逐帧导出 PNG 到系统临时目录（未写入仓库）。
- 墨迹 = `alpha ≥ 100` 且 `luma < 100` 的 V 像素；偏差 = 墨迹包围盒中心 − 画布中心（px，y 向下为正）。
- 最细笔画 = 行/列方向上连续不透明像素（`alpha ≥ 200` 且 `luma < 128`）的最小游程。
- 灰边 = 与透明像素相邻、且 `1 ≤ alpha ≤ 254` 的边缘像素占比；其中灰调像素（`50 ≤ luma ≤ 235`）单独计数。

## 实际尺寸集合

`16 / 20 / 24 / 32 / 48 / 64 / 256`，共 7 档、全部 32bpp；≤64 为 DIB+AND 掩码，256 为 PNG。
期望的 16/20/24/32/48/256 均存在，**无缺档**；64 为原有的额外观感档，保留。

### 判定

- 水平方向全部精确居中（dx = 0）。
- 垂直方向：16/20/24/32 为 −0.5px（偶数画布 + 奇数墨迹高度的亚像素极限，合格）；48/64 为 −1.0px（贴限值）；**256 为 −4.5px，超过 ≤1px 判据，是唯一硬性不达标项**。
- 16/24 的 V 两臂分离：白 counter 在字干段清晰（16px 开口 4 行、24px 开口 7 行），仅在顶点处自然汇合，非粘连。
- 无低对比灰晕：所有半透明边缘像素的 RGB 都接近纯白，属正常 alpha 抗锯齿；32/48 上可见的 1px 浅灰圆角描边来自设计本身的 hairline，不是灰晕。

根因：48（−1.0）、64（−1.0）恰为 256 的 −4.5px 按比例缩小（−4.5×48/256≈−0.84、−4.5×64/256≈−1.13），
说明全部帧都由同一 256 基准等比采样而来，只需修正 256 的 V 垂直位置即可。

## 修改

1. `tools/gen-icons.py`：`V_TOP, V_BOTTOM` 由 `245, 715` 改为 `263, 733`（+18@1024 基准 = +4.5px@256），
   使 V 墨迹包围盒垂直居中。**未改**字形、`V_DX`/`V_STROKE`、配色、圆角、描边宽与尺寸集合。
2. 重新执行 `python tools/gen-icons.py`（该脚本此前对仓库资产是逐字节可复现的，改动前已用 SHA-256 验证）：
   - `icons/veil.ico` 46,688 → 46,708 B，仍为 7 档、顺序与格式不变；
   - `icons/veil-32.rgba` 重新导出，仍为 32×32×4 = 4096 B（逐行自上而下、RGBA，与 `icon.rs` 的 `include_bytes!` 一致）；
   - `icons/veil-doc.ico` **未变**（SHA-256 一致，生成确定性）；
   - `icons/Markdown.png` **未动**：它是文档图标设计稿（`DOC_SOURCE`），不是应用图标 256 帧的同一源文件，也不属于本次问题。

## 验证

- `cargo check -p veil`：**通过**（`build.rs` 的 `include_bytes!` 尺寸无变化，`veil-32.rgba` 仍为 4096 B）。

  与 `app_tests/chrome_ui.rs`，属工作区中他人未提交的测试代码问题，与本次图标资产无关；故该命令无测试结果可引用。
  图标本身已通过字节级校验：`veil-32.rgba` 可被解码为 32×32 RGBA，且与 `veil.ico` 的 32 帧像素完全一致。


## 结论

**需要修改，已修**：修正 256 基准的 V 垂直位置（4.5px），其余尺寸由同一基准等比重采样，全部达到居中 ≤1px、无灰晕、16/24 两臂分离的判据。
未更换字形，未引入任何装饰；资产可由 `tools/gen-icons.py` 复现。
