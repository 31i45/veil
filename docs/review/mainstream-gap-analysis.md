## 1. 执行摘要

**Veil 现在的站位**：底座已经很强，问题不在「能力够不够」，而在「手感和表达够不够」。

- **三格强项**：架构（直接对标层 4/5，审美层 4/5）、UX（直接对标层 4/5）。因果键 memo 让「忘调失效」结构上不存在；自动保存五条件 + 崩溃快照 + 冲突三选一构成全项目唯一的 5/5 子锚；单文件 6,026,240 B、10 万字文档 40.76 MB，体积与内存对 Electron 系是碾压级。
- **一格系统性短板**：功能（三层均 2/5）。46 项真差距里只有 7 项高频，且**全部集中在「编辑手感」**——自动配对、行操作、查找选项、翻页与按词删除。这些不是功能缺失，是每日数百次微摩擦。
- **一格极化**：审美。中文排版禁则与中西文间距是 5/5（超过竞品公开能力），但排印（字体托管、行长无上限、H3–H6 压平）与动效（全局零过渡、光标常亮）是 2/5。**同一个维度里同时存在王牌与硬伤。**
- **口径必须修正的三处**：① 一致性不能说「全通过」，B 维为 CM 629/652 精确、630/652 规范化，GFM B 维 12/23；② 冷启动不可作卖点（30 ms 与 MarkText 打平）；③ 体积对比只能对单文件 exe（对 MarkText 37.6×，对系统 Notepad 仅 3.1×）。

**最值的五件事**（均为 S/M 成本、每日高频、不新增依赖，合计仅耗体积余量 3.4%–6.8%）：

1. **查找加大小写 + 全词**（`search.rs:240,260` 当前恒模糊）——把「人眼二次筛选」压回一次回车；
2. **替换态键盘可达**（当前只能点按钮）——批量改稿不再鼠标/键盘往返；
3. **括号/引号/标记自动配对**（全库无 autopair）——结构符号右半由编辑器回填；
4. **行操作**（Alt+↑/↓ 移动/复制行）——段落重排从四步收敛为一步；
5. **PgUp/PgDn + Ctrl+Backspace/Delete**（键位表显式缺失）——消灭「滚轮翻屏 + 逐字退格」。

**第 0 件（零体积，可无条件先做）**：`veil-egui` 旧名 11 处清理 + `Rect`/`contains` 四份同构收敛 + 导出菜单补省略号，约 1 天，可能净减体积。

**确认永远不做**（经分析维持，非本轮新增判断）：协作/CRDT、插件市场、移动端、PWA、任何网络请求、自动更新与遥测、Mermaid 全量渲染、独立富文本模型、安装器/文件关联注册、表格合并拆分与列宽拖动（10 类反目标，逐条附决策来源见 §4.5）；**拼写检查与多标签/多文档属「既有决策不做」**，不进路线图，拼写检查仅在四项证据齐备时可另立提案（§6）；**正则引擎按体积红线否决**，改用自研子集。

**一句话结论**：Veil 不缺「能写」的能力，缺的是「写得顺」的六处手感和「说得清」的三处表达。修这六处不需要新功能、不需要新依赖、不触碰 6 MiB 门禁，却能改变专业用户第一周的判断。

## 2. 方法论与证据等级

### 2.1 分析框架（七条原则的操作化）

| 原则 | 本项目的操作化判据 |
|---|---|
| 第一性原理 | 从「用户在思考时把文字落到屏幕」推导，不因「竞品有」立项；每条建议须回答它降低了哪个本质动作的成本 |
| 二八定律 | 按「覆盖 80% 日常写作场景的 20% 改进」排序；覆盖 <5% 的长尾默认降级，除非属信任/安全底线 |
| 软件设计的哲学 | 复杂性三来源（依赖/模糊/变更放大）逐项排查；深模块优于浅模块；「定义错误不存在」优于防御式兜底 |
| UNIX 哲学 | 单一职责、机制与策略分离、沉默是金（无扰输出）、过早优化排查 |
| 极简主义 | 每个菜单项、配置键、公共 API 都要能回答「删掉会失去什么」；装饰即负资产 |
| 一切皆是审美 | 字阶/行高/行长/基线、对比度比值、动效时长与曲线、对齐偏差、明暗对等性——全部落到可观测属性 |
| 代码整洁之道 | 命名表意、函数短小单一、参数少、无副作用惊喜、注释解释 why、测试钉死行为 |

### 2.2 证据等级与判定规则

- **证据等级**：实测（本机命令/截图，可复现）> 官方（官方文档/发布说明，标 URL 与访问日期 2026-11-07）> 二手（可信评测，标来源日期）。无可靠来源的格子标「无证据」，不进正文结论。
- **冲突裁决**：同一格两组打分相差 ≥2 时，以证据重裁；证据同等级取低分并附争议注记。
- **四分类强制**（G1 建立，防止把已决策项重新包装成待办）：
  - **①真差距**：Veil 弱且无既有决策 → 进路线图候选；
  - **②已排期**：v1.1/v1.2/v2.0 已有条目 → 不出新条目；
  - **③既有决策不做**：有台账（`release-and-roadmap`「明确不做」表 / rebaseline spec）→ 只允许单列「决策重开建议」，不得进路线图；
  - **④反目标**：永久排除（协作/CRDT、插件市场、移动端、PWA、任何网络请求、同步、遥测、自动更新、Mermaid 内嵌、富文本独立文档模型）→ 连建议都不进。
- **口径纪律**：任何「CommonMark/GFM 全通过」表述必须带维度后缀（A/C/D 维全通过；B 维 CM 629/652 精确、630/652 规范化；GFM B 维 12/23）。

## 3. 六维要点

> 每维只写「结论 + 证据锚点」，完整论证见分报告（§7.3 索引）。

### 3.1 架构：结构是对的，边界被规模稀释

**结论：架构层是全项目最健康的一维（直接对标层 4/5，强项）。**

- 强项：三 crate 严格单向 `veil → veil-ui → veil-core`；core 公开面仅 19 项；15 个端口 trait 注入使 headless 可测（`app_tests.rs:87-262`）；直接依赖仅 8 个；因果键 memo 让**生产代码手工失效归零**（7 个失效方法/30 个调用点，`cache.rs:38-42`），这是「第一性原理」式的正确抽象——不是把失效调对，而是让「忘调失效」不存在。
- 差距：`document/ + view/ + chrome/` 合计 11,180 LOC，而根级 20 个文件 20,525 LOC（46%）——`app/interaction/paint/editor` 实际构成**未具名的第四编排域**（中严重度，G1 由高降中：无行为后果证据）。App 有 11 个 `pub(crate)` 字段被 6+ 文件直接读写（`app.rs:374-391`），状态约束只靠注释与测试；`interaction.rs:12-15` 反向导入 `paint.rs` 的 7 个表格函数；`view/layout.rs` 2,911 行同时承担排版、Reveal 指纹、脚注代次与超限降级。
- 判断（软件设计哲学）：这不是「浅模块」问题，而是**深模块被摊平**——能力都在，但接口没有收口，于是变更放大。复杂度三来源中「依赖耦合」已被端口倒置解决，「模糊性」与「变更放大」集中在这 4 个根级文件。ADR-011 四条触发条件经 A 组核对**均未 trip**，维持现状。

### 3.2 代码质量：工艺高于平均，热点集中在绘制与平台层

**结论：六维 4/3/4/5/5/5（命名/函数/参数/副作用/注释/测试），整体优于多数 4 万行级项目，但有三处结构性热点。**

- 强项：副作用与测试两维满分级——1,091 个 `#[test]`（core 321 / ui 724 / veil 46），4 个性质测试钉死 memo/undo 不变量；端口 + Fake 全家桶让 UI 逻辑可在无窗口环境验证。
- 热点：① 绘制层「长而平」且同构——`paint.rs:116-152`（行内公式）与 `:153-194`（图片）控制流逐行同构，嵌套深度 9；② `Rect` + `contains` 四份同构定义（`geometry.rs:20`、`outline.rs:45`、`quick_open.rs:222`、`search.rs:27`），注释自称「避免第四份」却只收敛了一半；③ 平台层 21 个零测试文件、`fn wide` 逐字重复 ×4，`wic.rs` 136 行 unsafe COM 解码无任何测试。
- 口径纠错（G1 复核）：生产代码 `unwrap/expect/panic` = 10/26/1；`veil-egui` 旧名残留 11 处（此前 A/B 报 8 处）；`app_tests.rs` 8,773 行占全库测试 26.5%——测试强，但**单文件集中**使其成为合并冲突与检索成本的热点。

### 3.3 功能：日常写作闭环完整，但「编辑手感」缺三件基础设施

**结论：功能 × 直接对标层 2/5（差距）；46 项真差距中仅 7 项高频，且全部集中在「编辑手感」与「查找精度」。**

- 已达标：CommonMark/GFM 在 A/C/D 维 652/652、23/23 全通过；WYSIWYM 标记消隐保行高（`layout.rs:1536-1546`）使光标进出零跳动；17 条 README 能力全部落码，另有 6 项未宣传能力（崩溃恢复、大纲、Ctrl+B/I/K、缩放/F11、WIC 多格式插图、最近文件）。
- 高频缺口（每日写作必遇）：无括号/引号/标记自动配对（全库无 autopair 路径）、无行操作（Alt+↑/↓ 移动/复制行）、查找替换无大小写/全词/正则（`search.rs:240,260`）。这三项是「把手放在键盘上不离开」的本质动作成本，与「是否像专业编辑器」直接相关。
- 口径纪律：B 维一致性并非全通过——CM `B_EXPORT_EXACT 629/652`、`B_CANON 630/652`，GFM `B_CANON 12/23`（11 例 autolinks 仅观测）。对外表述必须带维度后缀，否则是夸大。
- 已排期 4 项（v1.2-3/4/5/6），既有决策不做 2 项（拼写检查、多标签），反目标 10 类——三者均**不得**计入「待办」。

### 3.4 交互：菜单做得比快捷键好

**结论：交互 × 直接对标层 3/5（持平），但 × 交互性能层 2/5（差距）——差距集中在「键盘肌肉记忆」。**

- 强项：菜单/右键分组、禁用态实时驱动、省略号约定（D §2），菜单键盘导航 `↑↓/←→/Enter/Esc` **代码已实现**（`interaction.rs:724-832`），H2「留 v2」的台账表述已过时，应回写而非重开；IME 工程完整度高（候选框三场景跟随 `app.rs:760-796`、preedit 纯视图态）。
- 差距（全部为高频、低成本）：PgUp/PgDn 文档翻页**显式返回 None**（`input.rs:200-201`，而 `page_scroll` 已存在）；Ctrl+Backspace/Ctrl+Delete 无按词删除分支（`input.rs:202-203`）；「替换/全部替换」只能用鼠标点（`view/search.rs:163-171`）。这三条是 VS Code/Sublime/Notepad++ 的通用地板，不满足则「专业感」直接受损。
- 无障碍是**唯一系统性空白**：UIA/AccessKit 零支持、高对比度模式无响应（winit 0.30 无 UIA provider）。场景频率长尾，但属「信任/公平」底线类，不因长尾而消失。

### 3.5 UX：信任机制是真正的护城河，但沉默过头

**结论：UX × 直接对标层 4/5（强项），其中「不丢稿」子锚 5/5——这是全项目最强的单点竞争力。**

- 强项：自动保存五条件 `dirty/has_path/!ime_active/!hold/idle`（`autosave.rs:39-54`）+ 崩溃快照魔数 `VEIL-RECOVERY-1`（`recovery.rs:13`）+ 冲突备份与三选一模态（`doc_state.rs:283-291,382-416`）；启动三级决议「崩溃恢复 > 会话恢复 > 传入文档」（`app.rs:414-431,470-480`）；外部修改/删除/占用/非 UTF-8 四类场景均有文案与恢复动作；BOM 剥离与保存还原、字节往返 100%。
- 差距：**自动保存完全沉默**，唯一信号是标题栏 `*` 消失——机制强于 Typora，感知却弱于 Typora；10 MB 级文件同步打开无进度反馈；CLI 打开非 UTF-8 文件时 `eprintln!` 在 GUI 子系统不可见，等价静默退出（`main.rs:27-30`）。
- 判断（第一性原理）：「不丢稿」的价值只有被感知才成立。信任不是实现属性，是**可观测承诺**。这是 P1 差异化的第一顺位。

### 3.6 审美：中文排版是隐藏王牌，排印与动效是明面短板

**结论：审美 × 直接对标层 3/5，但分面极化——中文排版 5/5、chrome 4/5，排印 2/5、动效 2/5。**

- 强项：行首 24 + 行尾 11 字符禁则表、WJ 胶水 + UAX#14 双保险、`……` 整体下沉、悬挂标点 v0（`layout.rs:1297-1323,2517-2550`）——**中文排版能力超过 Typora/iA Writer 的公开能力描述**，却从未对外表达；设计令牌单点统一（`theme.rs:193-334`），正文对比度 16.67/12.16 双 AAA。
- 差距（属性级）：字体完全托管系统解析、无 family 优选（`layout.rs:511`）；行长无上限，2560 px 下单行约 150 中文字（无 max-width）；H4=H5=H6 同为 1.1 倍且标题段距与正文同为 10 px（`layout.rs:57-65`）；光标常亮无闪烁（`paint.rs:1768-1794`）；全局零过渡动效；语法注释对比度 4.05/3.34、grid 装饰线 1.47/1.87，均低于 WCAG 阈值；列表无悬挂缩进。
- 判断（一切皆是审美）：审美差距不靠「加装饰」解决，靠**四个属性**——行长上限、字阶垂直分离、状态变化的过渡解释、非文本元素的最低对比度。四项都不需要新功能，只需**改数值与加定时器**，是成本最低、感知最强的一类改进。

## 6. 决策重开建议

> 本节单列，**不进路线图**。原则：只有「新事实」才能重开，禁止以「竞品有」为理由。

### 6.1 拼写检查：四个闸门同时满足才可重开（当前维持不做）

| 闸门 | 需要的事实 | 当前状态 |
|---|---|---|
| a | Windows `ISpellChecker` COM 在 Win10/Win11 的实际可调用性实测（COM 初始化、语言标签、返回码） | **未实测** |
| b | 中文词典来源与误报率，并说明与「中文为主」定位的关系 | **无证据** |
| c | exe 体积增量实测（须 <6 MiB；余量仅 265,216 B，增量 >212 KB 即不可行） | **未实测** |
| d | 与「系统输入法已覆盖大部分场景」口径的冲突说明 | **未说明** |

**结论：维持不做。** 四闸缺一即维持；四项齐备也只能生成独立提案并走 roadmap 变更日志，不得直接进 P0/P1。禁止以「9/13 标杆有」「唯一未覆盖惯例」作为理由。

### 6.2 ADR-011 wgpu：**不建议重开**

四条件均未 trip：击键 p95 远低于 15 ms 持续 3 次的阈值；内存 40.76 MB < 120 MB；无 FPS <55 证据；无渲染占比 ≥40% 证据。若未来探针同时触发四条，按 `v2.0-R1` 既有流程走，不需新决策。

### 6.3 H2 菜单键盘导航：不构成重开，只回写台账

代码已实现 `↑↓/←→/Enter/Esc`（`interaction.rs:724-832`），`v1.1-C1` 已标「已交付」；台账 L510 的「留 v2」表述过时。**动作：回写台账口径**，不新建条目、不排期、不占体积。

### 6.4 明确不设重开闸门的两项

多标签/多文档（③）与文件关联/安装器（④）：前者无任何新事实可推翻单文档定位，后者与单文件便携卖点结构性冲突。若未来单文档定位被其他决策推翻，须**先改 README 定位，再谈条目**，顺序不可倒置。
