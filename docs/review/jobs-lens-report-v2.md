## 一、评估口径

### 1.1 基线与范围

本轮评估的是 `converge-veil-under-jobs-lens` Phase 0–5 执行后的产品状态：HEAD `dfa05aa`，版本 `3.0.2`，工具链 rustc/cargo 1.99.1，Windows 11 企业版 10.0.26300，系统 DPI 144（150%）。评估只覆盖产品本体与已落盘证据，不评估提交规范本身。

### 1.2 只读声明

评估过程未修改任何产品源码、README、`component-inventory.md`、`follow-ups.md`、spec/tasks/checklist；只在 `docs/review/evidence/evaluation/` 新增 `phase-1.md`…`phase-6.md`，并新增本报告。未 push、未 amend、未回滚任何用户改动。

### 1.3 证据等级与标注

- **E1**：源码、配置或文档可定位；**E2**：仓库内已记录的实测、截图或原始样本；**E3**：由代码或证据推断，文中显式写“推断”。
- 每个维度分开写“事实 / 判断 / 与 v1 差异”；NOT RUN 集中列在第九节，不冒充通过。
- 历史数字（v1 引用的冷启动、RSS 等）只作对照，本轮一律使用当前 HEAD 证据。

### 1.4 评分标尺

5 = 行业标杆、可作为产品主张；4 = 明显优于同类、仍有个别可感知瑕疵；3 = 行业基线、可用但不构成优势；2 = 明显短板、日常使用会被绊住；1 = 严重缺失或破坏体验。

### 1.5 与 v1 的关系

v1 是 39/50 的基线诊断；v2 是对同一十维度在 Phase 0–5 之后的重新评分。v2 不推翻 v1 的历史判断，只回答两件事：哪些当时的缺口被闭合，哪些仍未被证据覆盖。

### ① 问题与意图 — 4/5

**事实**：起点仍是 Typedown 的启动摩擦，解法仍是纯 Rust、无 webview、单 exe（`README.md:19-21`，E1）；10 条反目标未变（`README.md:126-137`，E1）。Phase 1–5 没有扩张功能域，只补体验、证据、接缝与无障碍。

**判断**：意图与用户身份依旧收敛；命令面板让“能力可见”略有改善，但“为什么这样”仍主要靠 README。维度水平不变，4。

**与 v1 差异**：无。没有因为“做了很多工程”而抬分——意图传播仍是发现性问题。

### ② 体验与交互 — 5/5（v1 4，+1）

**事实**：`blink_active()` 只判断打印与 IME preedit，未命名草稿与已保存文档共用同一节奏（`app.rs:1650-1656`，E1）；`blink_flips_for_unsaved_draft_without_path` 等 5 项测试本次复跑通过（E2）。命令面板 `Ctrl+Shift+P` 的候选来自全部非分隔线菜单项（39 项），`Ctrl+P` 仍是快速打开，打印移到 `Ctrl+Alt+P`；中文子串过滤后回车可执行「打字机模式」「设置」，Esc 关闭并把焦点还给正文且不编辑正文（`app_tests/chrome_ui.rs:1378-1452`，E1/E2）。错误通知不自动消退、外部修改四选一、崩溃恢复说明对象/时刻/目录、动效克制均未被本轮改动，v1 的证据继续有效。

**判断**：v1 点名的两个缺陷——“首屏不眨眼”“没有统一入口”——都已被代码与回归测试闭合；除 AltGr 布局下 `Ctrl+Shift+P` 可能与字符输入冲突这一已记录的取舍外，没有发现新的用户可感知缺陷。给 5，是因为失败语义、焦点闭环与统一入口可以共同构成产品主张，而不是因为“新增了一个面板”。

**与 v1 差异**：+1。唯一扣分项从“两个真实缺陷”变成“一条有文档的键盘布局取舍”。

### ③ 视觉与表达 — 5/5（v1 4，+1）

**事实**：`content_span` 对除 `Full` 外的所有档位封顶 `40 全角 × 16px × scale`（即 640 逻辑 px），可用宽不足时取可用宽、居中且不裁切（`geometry.rs:116-142`、`theme.rs:557-560`，E1）；窄 / 1200 / 1920 三档 3 项几何测试本次复跑通过（E2）。`WIDE_WINDOW=1600` 门槛已删除（提交 `5b3d9a6`）。对比度断言、层级 ΔE、坏图 `[alt] + 占位框` 降级未被削弱。H4–H6 同字号仍是 README 明示的反目标（`README.md:137`，E1），按口径不计缺陷。

**判断**：v1 的扣分点是“公开承诺在常见窗口不生效”；现在承诺可验证地生效，且窄窗降级不裁切。40 全角 + 7:1 对比度 + 有尊严的降级，足以作为产品主张，给 5。

**与 v1 差异**：+1。这是全报告最明确的“承诺已兑现”项。

### ④ 能力与功能 — 4/5

**事实**：远程图片在 HTML 导出中仍被删除（离线契约），但正文顶部出现中英双语可见警告，覆盖 Markdown 图片与行内 `<img>`，并有 3 项测试（`jobs-lens-cross-surface.md` §1；本次复跑警告测试通过，E2）。Mermaid 暗色为“接受 + 披露”，7 项对比度测试通过，但其余 16 种图型暗色观感 NOT RUN，c4 `Rel` 标签无断言。PDF 表格与中文断行为“接受 + 披露”，并移交 Task 9；spike 结论 NO-GO，保留自研断行。核心编辑链路未被改动。

**判断**：从“静默丢失/静默降级”变成“可见警告或明确披露”，这是实质性改善；但 PDF/打印远程图片、Mermaid 图型覆盖、PDF 表格分页估算仍是用户能看见的差异。按标尺仍是“明显优于同类、仍有个别可感知瑕疵”，4。

**与 v1 差异**：0。改善的是诚实度，不是跨表面保真度。

### ⑤ 性能与稳态 — 4/5

**事实**：当前 HEAD 七项指标齐全：端到端首帧 **84.8 ms**（5 次中位，PASS）、击键内核 p99 **0.305 ms** / p95 0.109 ms（PASS）、峰值 RSS **52.6 MB**（PASS）、Private **33.76 MB**（参考）、体积 **14,170,112 B**（PASS）、SHA 已记录；**5005 块全量排版 296.55 ms，FAIL**（阈值 <100 ms，超出 196.55 ms）。首帧终点是 softbuffer `present` 成功，早于合成器真正上屏。自动保存/冲突/恢复的调度分离未被改动。

**判断**：4，不升不降。四项用户可感知指标通过，架构仍是它的存在理由；但全量排版 FAIL 说明“大文档重排/滚动余量”没有达标，不能把性能写成全绿。也不能降到 3：失败的是内部门禁，首帧、击键、内存、体积都通过。

**与 v1 差异**：分数相同，依据不同。v1 的 4 来自历史数字与架构推断；v2 的 4 来自当前 HEAD 实测，且附带一项明确 FAIL。这是本轮最重要的“同名不同义”。

### ⑥ 信息架构与导航 — 4/5

**事实**：`Ctrl+Shift+P` 命令面板与 `Ctrl+P` 快速打开并存，覆盖 39 个菜单项（E2）；设置表单 15 个字段，已包含「正文行高」（`settings.rs:243-254`，E1）；大纲仍在右栏 240（`outline.rs:13`），历史仍在左栏 300（`history.rs:15`）；快速打开仍只列最近文件 + 当前目录，不建全局索引。

**判断**：v1 的两个摩擦点——设置分层、无统一入口——都已修复；剩下的左右分置是明确的空间记忆成本，快速打开的窄范围是单文档取舍。维度水平仍是 4，不是 5：导航的“手感”还没有到可以当作产品主张的程度。

**与 v1 差异**：0。改进真实存在，但不足以跨过一个整分。

### ⑦ 适配与上下文感知 — 3/5

**事实**：高对比度真实系统切换 **PASS**（228 ms，Flags 126→127→126，平均亮度 240.4→39.2）；user_zoom 100/125（实际 120）/150/200 四档 **PASS**；系统 DPI 150% **PASS**。中文 IME、物理打印、副屏、系统 DPI 100/125/200 全部 **NOT RUN**。AccessKit 证据进一步披露：正文无 caret/选区/逐行语义，IME 在无障碍模式下未验证。

**判断**：证据比 v1 多，但缺口的位置没有变：对一个中文写作工具，IME 是主路径。高对比度与缩放不能替代 IME/打印/副屏。保持 3。

### ⑧ 数据、文件与持久化 — 4/5

**事实**：无私有格式、历史键稳定、冲突备份与恢复校验未被改动（v1 证据继续有效）。HTML 导出对远程图片不再静默丢弃，改为可见警告；PDF/打印仍降级为 alt / `[图片]`，只在 README 披露。

**判断**：“字不会丢”的底线仍在，导出迁移的断裂从“无声”变为“有声”，但保真度没有恢复。4。

**与 v1 差异**：0。改善的是告知，不是能力。

### ⑨ 可扩展与生长 — 3/5

**事实**：本轮把接缝做成了可测量的债：721 篇解析器差分、配置 round-trip、11 行跨表面断行差异、台账重新称重；选择性集成有六道门与观察触发条件；B 类保留理由与 `callouts` 完成状态已落账。插件/富文本/WebView 仍是反目标；功能增删仍无“加一减一”的成文规则。

**与 v1 差异**：0。

## 四、关键发现

### 4.1 P0 修复：五项有裁决，四项是“修”，三项是“标注”

- **版心**：从“>1600px 才封顶”改为“除 Full 外一律 40 全角封顶，窄窗铺满”，并有 640/1200/1920 三档测试。
- **光标**：闪烁不再依赖 `doc.path`，未命名草稿有专门回归。
- **行高**：设置界面可调，夹取规则与配置读取一致。
- **命令面板**：`Ctrl+Shift+P` 统一入口，打印让位到 `Ctrl+Alt+P`，39 个菜单命令可搜索执行。
- **远程图片**：HTML 导出加可见警告，不再静默丢图；PDF/打印仍是 alt 降级。
- **Mermaid 暗色**：接受现状 + 文档化；7 项断言覆盖 flowchart/mindmap/gantt/c4 stereotype，16 种图型未目检。
- **PDF 表格 / 中文断行**：接受 + 文档化，移交 spike；spike NO-GO，保留自研断行。

### 4.2 性能口径：首帧 PASS 不能掩盖全量排版 FAIL

- 端到端首帧 **84.8 ms**（74.4/76.8/84.8/87.6/109.6），阈值 100 ms，PASS；终点是 `present` 成功，严格说是“呈现就绪”。
- 击键内核 p99 **0.305 ms**、p95 0.109 ms，PASS；这是 `Session::apply` 段，不是视图全路径。
- 峰值 RSS **52.6 MB**、Private 33.76 MB；体积 **14,170,112 B**；SHA 已记录。
- 5005 块全量排版 **296.55 ms**，阈值 100 ms，**FAIL**；它解释大文档重排/滚动余量，不能用 84.8 ms 抵消。
- 结论：⑤ 的 4 分只能表述为“首帧与击键通过、全量排版未达标”，不能写“性能全面通过”。

### 4.3 接缝：差异可见、可测、可解释，但没有被消除

- **解析器**：721 篇（652 + 23 + 46），0 panic；块骨架差异 7 篇（1 front matter、6 块切口）；渲染差异 28 篇（24 CommonMark + 4 GFM），全部是已记录的序列化形式；对齐块文本差异 3 块；需修解析器差异 **0**。
- **配置**：15 字段 + 4 窗口键，4 项文件级 round-trip 测试通过，无行为漂移；记录 5 项既有容错语义，不静默改写。
- **排版**：产品宽度下 4 组语料 **11 行**内容不同，原因固定为容量（40 vs 43.8em）、半角禁则表差（9+3）、空格偏好、字宽；无丢字/越界/行首禁则违规。
- 含义：接缝债从“口头”变成“可回归”，但“屏幕/PDF 单一真值层”仍未统一。

### 4.4 选择性集成：NO-GO 是结论，不是失败

- `unicode-linebreak`：8 组语料 118 行，7 组断点完全一致；`mixed` 仅 2 行偏好差异，候选无质量净收益；只接受 `&str`，丢失 `LItem` 与 `last_space`，行为契约不通过 → **NO-GO**。
- `icu_segmenter`：数据 crate 3,141,236 B，超过当前 509,952 B 余量；不引入。
- `windows` / `image`：只观察，不引入；`windows` 不在依赖图（79 条手写 extern / 16 个 COM 槽位），`image` 已由 `arboard` 传入但只启用 `bmp`+`png`，非 PNG 走系统 WIC。两者都有明确再评估触发条件。

### 4.5 无障碍：最小树成立，语音流程缺席

- **事实**：UIA 树 46 节点（除根 45）、39 个菜单项、正文 `ControlType.Edit | "正文"`；菜单项 UIA Invoke 可打开设置模态（46 → 5），取消后回到 46；9 项 a11y 单测本次复跑通过。
- **限制**：正文只有前 8000 字节有界快照；无 caret/选区/逐行、无 UIA 编辑动作、候选列表未逐项暴露、节点无 bounds、Dialog 映射为 Window。
- **NOT RUN**：Narrator / NVDA 真实语音、中文 IME 在无障碍模式下、打印与副屏。
- **判断**：只能宣称“Windows UIA 可导航到常驻菜单项与正文入口，菜单项/模态按钮的 Click 走通产品路径”；不能宣称完整屏幕阅读器兼容。Phase 5 出口因此 **FAIL**（不是实现失败，是证据未闭合）。

### 4.6 体积：余量已经进入“先称重再决定”的区间

- Task 8 基线 **14,170,112 B**（13.51 MiB），余量 509,952 B。
- AccessKit 接入后 **14,362,624 B**（13.70 MiB），实测增量 **+192,512 B**，余量 **317,440 B**；本次核对文件大小与 SHA-256 均与证据一致。
- Mermaid 内嵌 JS 单独归因 **3,213,314 B**；任何新依赖必须先做体积 spike，不能再“先接上再测”。

## 五、最强与最弱

### 5.1 最强三维度

1. **⑩ 伦理与控制权（5）**：数据、网络、注意力三重克制没有被本轮稀释；AccessKit 也是本地、可关闭、无网络。
2. **③ 视觉与表达（5）**：版心承诺从“只在超宽屏生效”变为“常见窗口即生效”，对比度与降级仍有测试；这是本轮唯一“公开承诺被兑现”的维度。
3. **② 体验与交互（5）**：失败路径的信任感、焦点闭环、统一命令入口现在同时成立；从“好但缺一口气”变成“可当作产品主张”。

### 5.2 最弱三维度

1. **⑦ 适配与上下文感知（3）**：中文 IME、物理打印、副屏、系统 DPI 变体仍未走通；对中文写作工具，IME 是主路径而非边缘场景。
2. **⑨ 可扩展与生长（3）**：接缝可测是进步，但生长仍窄，功能增删没有成文判据；治理改善不等于生长能力提升。
3. **⑤ 性能与稳态（4，4 分中最弱）**：四项通过、一项 FAIL；“全量排版 296.55 ms”是目前唯一有明确阈值的失败，不能被首帧 84.8 ms 掩盖。
