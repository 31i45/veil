## 2. 启动时间 main → 首帧（§8.2）

### 方法

- PowerShell `System.Diagnostics.Stopwatch` 从 `Start-Process` 启动到 `user32!IsWindowVisible(hWnd)` 返回 true。

- 每次间隔 ≥500 ms，第 1 次冷启动后磁盘缓存已热。

## 3. 击键延迟 p95（§8.3）

> 以下数据来自 `cargo run --release -p veil --example bench_typing`，headless 基准。
> 纯逻辑不含 GPU present；脏块重排版为实际渲染前的唯一瓶颈。

### bench_typing 输入文档

- 构造 715 轮 Markdown → **5,005 个 block**（段落 / 列表 / 代码块 / 引用 / 分隔线）。

### 结果

| 场景 | p50 | p95 | 单位 | 说明 |
|---|---|---|---|---|
| **Session::apply**（单次核心插入） | 67.70 | **79.80** | µs | 编辑内核原子操作 |
| **脏块重排版**（dirty layout） | 240.00 | **476.70** | µs | 渲染管线唯一瓶颈 |
| 全量 blocks()×12 遍历 | 1,388.80 | 1,577.90 | µs | 病理枚举（正常路径不走） |
| 1920×1080 Frame 分配+填充 | 1.89 | 2.09 | ms | 含内存分配 |
| Frame 复用（reset，零分配） | 0.42 | 0.58 | ms | 稳态渲染 |
| 冷启动（open + 全量排版） | 572.40 | 617.74 | ms | headless，5 次 median/max |

### 结论

- 核心编辑延迟 p95 = 79.80 µs，远低于 16ms 帧预算。
- 脏块重排版 p95 = 476.70 µs，仍远低于帧预算。
- 稳态帧填充 p95 = 0.58 ms（复用缓冲）。
- 真实 GUI 渲染需再加 GPU present 开销（预计 ~1-3 ms），总 p95 仍 < 5 ms。

## 4. Working Set / Private Bytes（§8.4）

> 100k.md 生成方式：`2000 行 × ~73 字符/行 = 144,893 字符`，全为普通段落（无 Markdown 标记）。
> 测量为打开后稳态，sandbox 环境无法真的滚动 20 页；滚动场景在真机复测。

### 100k.md（144,893 字符）

| 指标 | 值 |
|---|---|
| **Working Set** | **141.86 MiB** |
| **Private Bytes** | **139.74 MiB** |

### test.md（22,139 字符）小文档对比

| 指标 | 值 |
|---|---|
| **Working Set** | 63.38 MiB |
| **Private Bytes** | 38.92 MiB |

### 说明

- Working Set 与 Private Bytes 分列记录，不混用口径。
- 大文档（100k）相对小文档（test）Working Set 增加 ~78.5 MiB，Private Bytes 增加 ~100.8 MiB。
- Private Bytes > Working Set 说明进程分配了大量私有虚拟内存但物理驻留部分较小；这是 Rust release 构建 + arena 预分配的常见形态。
- bench_typing headless 峰值堆：**6.25 MiB**（3.4 百万次分配）。真实 GUI 进程的大量常驻内存来自窗口 / 字体 / 渲染缓冲 / Mermaid 离线引擎（惰性初始化）。
