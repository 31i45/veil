> 状态：**代码修复已落地并单测覆盖；真机组字/候选窗走查 NOT RUN（需要人在场切换微软五笔/拼音）**

## 1. 代码层已证实的事实

| 事实 | 证据 |
|---|---|
| Veil 上报的是光标区域**左上角**（行顶，物理像素） | `crates/veil-ui/src/app.rs` `set_ime_area()`；`crates/veil-ui/src/interaction.rs` `caret_screen()` |
| winit 0.30.13 把 `COMPOSITIONFORM.ptCurrentPos` 写成 `y + height`（行底） | `winit-0.30.13/src/platform_impl/windows/ime.rs` `set_ime_cursor_area`；`CANDIDATEFORM` 却用行顶 |
| 旧实现把组合串位图直接 blit 在光标处，后方正文不位移 | 旧 `paint_overlay.rs`：`frame.blit(...)` 前无底色填充，仅 1px 前景色下划线 |
| 结果 | 组合串与光标后的正文逐字叠在一起，微软五笔/拼音组字时“分不清” |

“CUAS 渲染”不是本仓库存在的模块名；可核实的机制是「自绘 preedit 覆盖层 + 系统组合窗锚点偏移」两件事叠加。

## 2. 本轮修改

1. **锚点纠正端口 `ImeAnchor`**（`crates/veil-ui/src/app.rs`）
   - `set_ime_area()` 在 `set_ime_cursor_area` 后用同一组坐标调用
     `ports.ime_anchor.correct(hwnd, x, y, 2.0, h)`；无窗口时 `hwnd = 0`。
   - 产品层 `crates/veil/src/platform/ime.rs`：`ImmGetContext` →
     `ImmSetCompositionWindow(CFS_POINT, x, y)` →
     `ImmSetCandidateWindow(CFS_EXCLUDE, [x, y, x+2, y+h])` → `ImmReleaseContext`。
   - 候选窗与组合窗统一回到光标左上角，不再出现“组合窗低一行”。
2. **组合串可读性**（`crates/veil-ui/src/paint_overlay.rs`）
   - 贴位图前先按组合串尺寸铺不透明块底色，再叠 2px 主题强调色下划线。
   - 组合串不再与正文笔画混叠；Esc 取消/提交路径与撤销栈不变（组合串始终不进文档）。
3. 查找栏 / 快速打开 / 模态的自绘输入未改动，仍走各自原有的 preedit 显示。

## 4. 真机走查（NOT RUN，需人在场）

步骤（每条分别对「微软五笔」「微软拼音」执行）：

1. 打开 Veil，载入一段中文，光标停在句子中间（不是行尾）。
2. 输入一个词组，确认：组合串出现在插入点、不压住后续文字、候选窗在插入点下方而不是低一行。
3. 候选翻页一次（`-`/`=` 或 `[`/`]`），确认候选窗跟随成行。
4. 按 Esc 取消，确认无残留下划线/残字，正文未变、撤销栈未多一步。
5. 输入中文标点，确认全角标点落在插入点。
6. 在行尾、段落首、折行处各重复一次步骤 2。

通过标准：六步全部符合；任一步失败记录窗口截图与该 IME 版本，回退到“自绘 + 锚点纠正”组合继续定位。
