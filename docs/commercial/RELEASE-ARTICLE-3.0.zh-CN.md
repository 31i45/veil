# 31 天，我把一个 Markdown 编辑器写到了 3.0

> **历史发布快照：v3.0.1，2026-11-23。** 本文保留当时叙事，但数字、兼容性与签名状态只对应文中标明的历史构建或测试，不是当前 v3.0.2 的复测或发布验收。当前功能与隐私边界以双 README 和 `PRIVACY.md` 为准。

2026 年 10 月 24 日深夜，我写下了 Veil 的第一份设计文档。

起因很具体：Typedown 是我在 Windows 上最喜欢的 Markdown 编辑器，没有之一，但它每次启动要几十秒到几分钟。一个写笔记的工具，打开比泡一杯咖啡还慢，这件事不该存在。于是我决定自己造一个。

今天，2026 年 11 月 23 日，Veil 发布 v3.0.1。

## 这 31 天

- 10 月 24 日：写下设计文档与前三份 ADR，确定「纯 Rust、无 WebView、单文件 exe」
- 11 月 6 日：v1.0.0 发布
- 11 月 21 日：v3.0.0 发布，Mermaid 改为进程内离线渲染，图表源码不再离开本机
- 11 月 23 日：v3.0.1，构建管道与仓库健康度收口

31 个自然日里，有 30 天留下了开发记录，293 次提交。这不是一个周末项目，是把每一天都填满的结果。

## 它在 v3.0.1 时是什么

一句话：一个安静、快速的本地写作表面。

- **一个 exe**：v3.0.1 当时记录为约 13.4 MiB，不能用作当前 v3.0.2 的体积证据。没有 Electron、Chromium 或 WebView，不需要单独安装应用运行时；仍使用 Windows 系统组件与系统 DLL。
- **历史性能记录**：145–190 ms 是 2026-11-05 pre-v3 构建 `main → 首帧` 的 5 次最小–最大值，不是中位数；约 2.6 ms 是 2026-11-21 commit `0d229eb` 的击键 p95 历史结果；40.76 MB 是 2026-11-05 打开 10 万字文档、20 页深滚动后的 Working Set/RSS 单点，不是 Private Bytes。它们都不是 v3.0.2 复测。
- **中文写作循环**：增量解析、语义选区、表格编辑、公式、图片、脚注、锚点、大纲、查找替换（含正则与捕获组）、版本历史、多窗口。
- **原生矢量 PDF 与自包含 HTML 导出**：多级书签、CJK 字体子集化，文本输出可搜索、可复制。
- **离线 Mermaid**：QuickJS + 完整 mermaid.js 在进程内渲染，图表渲染本身不联网；远程图片与显式打开外部页面是独立边界。
- **无遥测、云同步或后台更新检查**：检查更新只手动打开官方 Release 页。崩溃与诊断报告本地生成、不自动上传；远程图片默认关闭，持久开启后会按需请求。MIT 许可。

## 几句实话

Veil v3.0.1 发布时只支持 Windows x64（Windows 10 / 11），界面只有中文；正式验收环境为 Windows 11 23H2+。当前 v3.0.2 已按 Windows 显示语言提供中英文界面，具体规则以 README 为准。

当时发布包使用自签名开发证书，**会显示未知发布者，SmartScreen 可能拦截**。生产证书需要实名与付费，当时尚未推进。下载后应按 README 从同一 Release 获取产物与侧车文件并校验 SHA-256；历史文章中的体积或摘要不能用于当前产物核验。

渲染层面也有边界。PDF 的中文换行是简化版禁则处理，和编辑区不会逐像素一致；部分 Mermaid 图表在深色主题下的对比度仍是已知且已记录的限制。这些是当时已公开的边界；当前限制以双 README 的「已知限制」为准。
