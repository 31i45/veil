# ADR-003: mark bias 与 inline 边界光标亲和性（affinity）规则

## 状态：已采纳

## 背景

inline-WYSIWYG 最大的交互 bug 源：光标位于 `**bold**` 的 `**` 与 `b` 之间（或任何 inline 节点边界）时，输入的字符是否继承格式？此问题不定义清楚，所有嵌套 inline 编辑都会产生「幽灵格式」或「格式丢失」类缺陷。且 Reveal 展开/收起引起文本长度变化时，光标位置如何映射，也依赖同一套规则。

原设计只说「光标移入节点自动 Reveal」，未定义边界归属与 Reveal 下的编辑语义。本 ADR 补齐。

## 决策

1. **Mark 带 bias**：`Mark { offset, bias: Left | Right }`。插入发生在 mark 处时：bias=Left 的 mark 跟随其左侧内容（插入物出现在 mark 之后）；bias=Right 的 mark 跟随其右侧内容（插入物出现在 mark 之前）。删除区间时：区间内 mark 被移除，边界 mark 按 bias 收敛。
2. **inline 边界插入规则（光标恰好落在节点边界时）**：

| 场景 | 归属规则 | 效果 |
|---|---|---|
| 左边界（`\|**bold**`） | 新字符归属**外侧** | 不产生「无意进入格式」 |
| 右边界（`**bold**\|`） | 新字符归属**外侧** | 不产生「格式拖尾」 |
| 光标从节点**内部**移动到右边界再输入 | 归属**内侧** | 支持「继续写粗体」 |
| 光标从节点**外部**移动到右边界再输入 | 归属**外侧** | 支持「在粗体后写普通文本」 |

   即：归属不取决于位置本身，而取决于光标的**来向**（affinity 状态）。
3. **affinity 模型**：光标对象携带 `affinity: Inside | Outside`；跨越边界（方向键、鼠标点击、删除）时按上表重置；同侧连续输入保持 affinity。此状态为**内核光标属性**，因为它决定文本归属，不只是视觉策略。
4. **Reveal 下的编辑语义**：Reveal 展开时，用户看到的是原始标记文本；此时一切编辑按纯文本处理（输入到标记字符之间就是修改标记本身），affinity 规则不介入。Reveal 收起时按上表归属。
5. **删除规则**：Backspace/Delete 跨边界时先作用于边界标记字符（Reveal 语义），再作用于内容；空格式节点（如 `****` 内容为空）在下一次编辑时自动清理为纯文本。

## 后果

- 好：Typora/Typedown 的「格式拖尾」「无法退出格式」两类经典缺陷从规则上被消除；Reveal 与 affinity 结合后，边界编辑行为完全可测试（每条规则可写单元测试）。
- 坏：光标对象不再是纯 offset，带有状态； IME 组合期间 affinity 冻结（preedit 提交前不允许边界规则介入）需特别处理。

## 替代方案

- 「位置决定归属」静态规则（无 affinity）：无法同时满足「继续写粗体」与「粗体后写普通文本」两个互斥需求，否决。
- 「永远归属内侧」（Muya 早期行为）：产生幽灵格式，用户无法退出格式，否决。
- 「永远归属外侧」：无法继续扩展格式，用户必须重新标记，否决。
