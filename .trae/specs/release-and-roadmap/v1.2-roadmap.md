# Veil v1.2 Roadmap

目标窗口：**v1.1 收尾后约 4–6 周（无硬 deadline，按体积预算推进）**。
状态：v1.2-1（PDF 直接导出）与 v1.2-2（源码模式）已在 converge 批次交付；HTML 主题 CSS 导出、GFM 脚注与文档内锚点已在 v1.2 文档增强批次（2026-11-06，Unreleased）交付；候选池剩余表格可视化子集、排版设置、PDF 书签与字体子集化。

---

## 永恒设计原则重申

**Veil 是单机单用户纯离线 Markdown 编辑器。永不引入多用户协作、网络同步、云端存储、任何形式的网络访问。**
本 roadmap 中所有条目均为单机单用户、可完全离线完成的场景；任何需要联网、账号或多端同步的方案一律不立项。

---

## 判定口径

| 用词 | 定义 |
|---|---|
| **标配** | 同类 Markdown 编辑器普遍具备、缺失会被用户直接感知为"不完整"的能力。 |
| **特色** | 同类产品少见或实现路径独特（如自研状态机、自绘 chrome），构成 Veil 差异化卖点的能力。 |
| **鸡肋** | 技术上可做、但使用频次低或收益被现有能力覆盖，投入产出比明显不划算的能力。 |
| **不值得** | 与单机单用户纯离线定位冲突，或需要新增外部运行时依赖 / 持续维护成本的能力。 |
| **证据债** | 功能已实现但缺少可复现的真机或自动化证据，需要补测、补录、补断言，而不是补代码。 |

## 候选池

优先级：**P1** = v1.2 首发应交付；**P2** = 有余量再做，可顺延到 v1.3。当前候选均为 P2。工作量：S ≈ 1–2 天，M ≈ 3–5 天，L ≈ 1–2 周。

| 编号 | 条目 | 优先级 | 依赖前置 | 体积影响评估 | 验收标准 | 工作量 |
|---|---|---|---|---|---|---|
| v1.2-3 | 表格可视化编辑（剩余子集）：合并/拆分单元格、列宽拖动 | P2 | v1.1-B3（已交付） | 预计 +0.05–0.15 MiB（仅 UI 交互与命中测试，不新增依赖） | GFM 无法表达合并单元格与列宽，必须定义扩展语法（HTML 表格或自定义属性），且所有结构性变更可回落为 Markdown 源文本 | L |
| v1.2-4 | 字体 / 字号 / 行宽设置：扩展 `config.toml` | P2 | v1.2-1（已交付，页边距配置项已就绪） | 预计可忽略（配置读取 + 排版参数接线，不引入字体文件或新依赖） | 三项设置写入 `config.toml` 并在重启后保持 | M |
| v1.2-5 | PDF 书签 / 大纲 | P2 | v1.2-1（已交付） | 预计可忽略（仅 PDF 结构对象与标题映射） | 导出 PDF 含按标题层级生成的书签，跳转页码正确；关闭目录页时书签仍可用 | M |
| v1.2-6 | PDF 字体子集化 | P2 | v1.2-1（已交付） | 需实测；若嵌入字体使 exe 或产物突破 6 MiB 门禁则降级为系统字体引用 | 导出 PDF 在其他机器上字形一致、文件体积可控，不突破 6 MiB | M |

## 能力基线（已具备，不再立项）

以下能力 v1.x 已实现并有测试或真机证据，仅作为候选池的去重基线，不重复立项：

- 查找替换
- 大纲面板
- 快速打开（Ctrl+Shift+P）
- 自动保存
- 崩溃恢复（recovery.dat）
- 外部修改提示与覆盖前备份
- 打印（Ctrl+P 系统打印对话框）
- 直接导出 PDF（`Ctrl+Shift+E` / 文件菜单；目录、页码、页边距可配置）
- 源码模式（`Ctrl+/`，全文源码视图）
- HTML 导出（Ctrl+E；内联 CSS 跟随当前浅/深主题）
- GFM 脚注（`[^id]` 引用/定义、`Ctrl+单击` 双向跳转、导出文末脚注列表）
- 文档内锚点跳转（`[文本](#slug)`、导出标题 `id`、重复标题去重）
- 链接用系统默认程序打开（`Ctrl+单击`、右键「在浏览器中打开」）
- 图片粘贴 / 拖拽插入
- 公式（latex-rust 纯 Rust 路径）
- 专注模式 / 打字机模式
- 链接主题色（浅 `#2B6CB0` / 深 `#7FB4F5`）
- 菜单键盘导航（↑/↓ 选择、Enter 执行、Esc 关闭）
- 表格行列增删与列对齐（右键菜单，一次 undo）
- 单元格富文本（非活动格渲染标记，活动格显示源码）
- 性能探针（`VEIL_PERF_PROBE=1` + `tools/walkthrough.ps1 -Perf`）
- 代码块语法高亮：16 种语言，自研逐行状态机，不引入 syntect
- CJK 排版：中英自动间距、行首行尾禁则、满行悬挂标点
- 自绘 chrome：菜单栏 / 状态栏 / 滚动条

## 明确不做

| 条目 | 判定 | 理由 |
|---|---|---|
| Mermaid 全量渲染 | 不值得 | 渲染引擎体积与维护成本远超预算；最多降级为只读代码块展示 |
| 插件系统 | 不值得 | 破坏单文件 exe 与确定性行为，且需要稳定的外部 API 契约 |
| 多标签 / 多文档 | 不值得 | 与"单文档定位"冲突，会牵动文档模型、崩溃恢复与外部监听的全部假设 |
| 拼写检查 | 鸡肋 | 需内置词典与语言模型，体积代价高；系统输入法已覆盖大部分场景 |
| 安装器 / 文件关联注册 | 不值得 | 便携单文件是核心卖点，安装器会引入写注册表与卸载链路 |
| 自动更新与遥测 | 不值得 | 违反纯离线原则，任何网络访问均属违规 |

---

## 体积预算门禁

- 上限：**6 MiB**。
- 当前：release exe **5,985,280 B（≈ 5.71 MiB）**，余量约 **0.29 MiB**。
- 任何条目若预估使 exe 超限，必须降级或否决，不得先合入再优化。
- 禁止新增外部运行时依赖（无 webview、无 Chromium、无可选运行时），依赖黑名单沿用 `tokio`、`wasmtime`、`webview2-com`/`wry` 等。
- 每个条目合入前需给出 release 构建实测体积，并与本条目的预估区间对照记录。
