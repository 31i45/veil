# Veil v2.0 Roadmap

目标窗口：**v1.1 走查收尾后 6–12 个月**（无硬 deadline，触发式推进）。
状态：v1.0 已发布；F1 源码模式、F5 PDF 导出、F3 列对齐已在 converge 批次交付；v2.0 架构与渲染条目仍为触发式。所有条目为单机单用户场景。

## 事实校准（2026-11-06）

规划前先对齐既有事实，避免把已完成的工程重复排期：

- **代码块语法高亮已在 v1.0 实现**，实现于 `crates/veil-ui/src/view/highlight.rs`：16 种语言、自研逐行状态机、无 syntect 依赖；已在 `crates/veil-ui/src/view/layout.rs` 接线并有单测。**不再作为 v2.0 缺口**。
- **cosmic-text 自 v1 起即为排版内核**（见 `README.md` 架构表）。任何“替换 cosmic-text”的表述作废。
- **架构整改计划的真实路径**是 `.trae/documents/veil_core_remediation_plan_v2.md`；`docs/review/` 下没有该文件，引用以 `.trae/documents/` 为准。

## 当前状态（2026-11-06 探针基线）

- `cargo test -p veil-core --release --lib bench_edit_reparse_history -- --ignored --nocapture`：10 万字文档 50 次编辑，`edit=6.10 µs/次`、`reparse=830.39 µs/次`、`history=0.57 µs/次`（末次重扫 4 行）。
- release exe = 5,914,112 B（约 5.64 MiB，门禁上限 6 MiB）。
- 结论：架构批次 **A1–A5** 与渲染后移 **R1–R3** 本轮**均未触发**（单次编辑只重扫末次 4 行、history 0.57 µs、体积仍在门禁内），因此不在 v1.1/v2.0 排期；后续以探针数据复核。

## 永恒设计原则重申
**Veil 是单机单用户纯离线 Markdown 编辑器。永不引入多用户协作、网络同步、云端存储。**

### 明确排除（永不在 roadmap 中出现）
- ~~CRDT / OT 协作~~
- ~~远程同步 / 云端存储~~
- ~~多人实时编辑~~
- ~~插件远程调用 / 网络 API~~

### 单机定位不变
- 单文件 exe（v1.x 门禁 4–6 MiB）、冷启动 ≤ 300 ms、零外部运行时、零网络依赖
- veil-core 永远是纯文本 + 增量解析内核（零 GUI / 零异步）
- veil-ui 永远是 winit + softbuffer 自绘 chrome（无 egui / 无 wgpu，除非 ADR-011 触发条件满足）

## 渲染后移（ADR-011 · wgpu 触发条件）
> **四条同时满足才启动**：
> 1. 击键 p95 ≥ 15 ms 持续 3 次探针
> 2. 内存占用 ≥ 120 MB
> 3. 1920×1080 窗口布局明显卡顿（探针 FramesPerSecond < 55）
> 4. profile 显示渲染占比 ≥ 40%
> 四条同时满足 → 成立 `veil-render` 新 crate（wgpu + cosmic-text 重写），v1.x 的 winit + softbuffer 继续维护到 v2.0 GA。
> **只要一条不满足，就继续优化现有渲染路径**。
> **当前实测（2026-11-06）**：击键 p95 3.37 / 5.20 / 9.25 ms、内存 40.76 MB，四条均未触发，不提前做。
> cosmic-text 已是 v1 排版内核，如需演进只做版本升级与排版参数调优，**不作为“替换工程”**。

| # | 条目 | 触发条件 | 依赖前置 | 优先级 |
|---|---|---|---|---|
| v2.0-R1 | wgpu 新 crate 原型 | ADR-011 四条件全满足 | v1.x 发布稳定（≥ v1.2） | P1 |
| v2.0-R2 | softbuffer → wgpu 过渡 | R1 原型性能验证 ≥ 2× 提升 | R1 | P1 |
| v2.0-R3 | 自绘 chrome 迁移（菜单/状态栏/滚动条） | R2 稳定 | R2 | P1 |

### 已知限制（2026-11-06）

- PDF：**无书签/大纲、无字体子集化**；导出依赖系统「Microsoft Print to PDF」，未保存草稿或无 PDF 打印机时回退打印对话框。补强项见 v1.2-5 / v1.2-6。
- 表格：GFM 无法表达合并单元格与列宽；列对齐已交付，**无合并单元格/列宽拖动**，剩余子集见 v1.2-3。
- 源码模式：是同一 Markdown 文档的视图切换，不是独立的富文本文档模型。

## v2.0 不做（架构后移 / 延期）

| # | 条目 | 条件 | 归属 |
|---|---|---|---|
| - | 任何多用户协作 / CRDT / 同步 | 永不在 roadmap 出现 | 永恒排除 |
| - | wgpu 提前引入 | ADR-011 四条件任一不满足 | 渲染后移 |
| - | 单机插件系统 | 纯离线单机没有插件生态来源，却要承担沙箱与 API 兼容成本 | 不做（原 v2.0-F4） |
| - | 插件远程分发 / 市场 | 明确边界 | 单机插件不做 |
| - | 移动端 | 无需求 + 架构差异大 | 延期 v3+ |
| - | PWA / 云存储 | 明确不做 | 永恒排除 |

## 时间线示意

```
v1.0 (2026-11) ──> v1.1 (2026-12) ──> v1.2 (2027-01) ──> v1.3 (2027-02) ──> v2.0 (2027 Q3+)
  门禁全过         硬件补测            渲染路径优化         ...探针数据...          ADR-011 触发后启动
```

**关键**：v2.0 没有硬 deadline。wgpu、架构批次、Mermaid 都是触发式。如果 v1.2+ 探针数据持续绿色，v2.0 可能一直推迟——这是**好事**，代表 v1.x 架构足够稳定。
